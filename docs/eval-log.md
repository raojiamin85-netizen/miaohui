# 妙回 · 评测日志

> 阶段 4 的原始记录。每次拉取反馈后追加一节：数据快照 → 发现的问题 → 对应规则改动。
> 这份文件是生成质量评测的证据链（"像人评分从 X 提到 Y"）。

## 快照 001 · 2026-09-28（v0.1 规则上线后首批数据）

- 总反馈：24 条（好评 12 / 差评 12），差评全部附了原因 —— 数据质量很好
- 分意图表现：
  - 表达关心：6 条，**0 差评**（表现最好）
  - 答应并推进：6 条，2 差评
  - 接住话头：12 条，**10 差评**（重灾区）

### 问题诊断

**问题 1 · 接住话头差评率 83%，全部集中在"被夸显嫩/年轻"场景**

12 条差评原因归类：

| 原因类型 | 条数 | 典型案例 |
| --- | --- | --- |
| 自贬式幽默引起不适（"搬砖""熬到返老还童""多搬十年砖"） | 5 | "被你这么一夸，感觉又能多搬十年砖了" |
| 反过来恭维对方（"你看着才年轻""跟着你干活心情好"） | 4 | "哪里，你看着才年轻，我得取取经" |
| 场合错配：对领导/初次见面开玩笑 | 3 | "哈哈全靠美颜撑着，本人糙多了" |

**根因**：模型不知道"对方是谁"。同一个"被夸"，对朋友可以皮一下，对领导/长辈/初次见面必须稳。v0.1 没有给模型这个信息。

**问题 2 · 答应并推进的 2 条差评**：对领导用"哈哈别呀，钱一到我立马转"这类轻佻玩笑 —— 同样是身份缺失问题。

### 对应改动（v0.2）

1. 新增输入项「对方是谁」（领导/长辈/初次认识/同事/朋友/家人），随每次生成传给模型
2. 系统提示词新增规则：对领导/长辈/初次认识的人禁用玩笑和网络梗、禁用恭维对方；被夸时大方接受+简短感谢，禁用自贬（搬砖/社畜/苦命类自嘲）
3. 意图指南修正：「接住话头」明确"被夸→大方接受"；「答应并推进」明确"承诺留有余地"

## 快照 002 · 2026-10-15（生成耗时实测 —— 为什么等了两分钟）

触发：真实使用中报「生成一条回复等了两分钟」，而另一些场景十来秒就出来了。

### 定位过程

先看代码，模型是这么选的：

```js
const models = await cloud.llm.models.list();
model = models.find(m => m.disabled !== true);   // 取列表里第一个未禁用项
```

再拉真实的模型列表：32 个模型，**排在第一位的平台默认模型是 `auto`**（"自动为每个任务匹配最优模型，积分倍率随之浮动"）。也就是说，产品实际上一直在用平台的路由器，而它会把任务分派给谁、要算多久，我们既不知道也控制不了。

然后量。用**同一条真实 prompt**（上下文「对方：你好」+ 意图「接住话头」+ 身份「领导」）跑不同模型，单次 75 秒上限（`scripts/probe-latency2.cjs`）：

| 模型 | 首字 | 全部完成 | 输出 | 备注 |
| --- | --- | --- | --- | --- |
| `auto`（原本在用） | **>75s 无输出** | **>75s** | 0 字 | 另一次实测 125.3s |
| `deepseek-v4.1-flash` | 0.9s | **1.5s** | 156 字 | 复测 2.8s / 5.7s |
| `glm-5.3-flash` | 3.1s | 4.2s | 143 字 | 复测 5.9s / 7.6s |
| `step-5-preview` | 55.5s | 55.6s | 142 字 | 慢 |
| `hy4-preview` | 57.0s | 57.6s | 166 字 | 慢 |
| `hy3` | 26.0s | 26.5s | 238 字 | 复测连接被重置 |

关键发现：**慢是慢在"首字"**（模型想完才吐第一个字），不是慢在"输出的字多"。所以"让模型少写点字"这类优化没用，只有换模型有用。同一张聊天截图做识别：`deepseek-v4.1-flash` 2.8s、`glm-5.3-flash` 3.2s，识别内容都对。

### 对应改动（v0.15）

1. **显式候选链**：`PREFERRED_MODELS = ["deepseek-v4.1-flash", "glm-5.3-flash", "deepseek-v4-flash", "glm-4.6v"]`，命中不了再退到其它"支持图片"的模型；`auto` 与 `default` 被明确排除（只收支持图片的，因为截图识别复用同一个模型）。
2. **首字看门狗**：首选 8 秒不吐字就自动换下一个候选（最多试 3 个），用户不必陪一个抽风的模型等到底；取消按钮只中断当前这一次尝试。
3. **等待期可见**：流式输出是 JSON、本来要全部收完才能解析，现在边收边把已经写完的候选先显示出来（"已经写好 1 条（我在的，你说）"）；超过 8 秒还会把当前在用的模型名显示出来，便于反馈"哪个模型慢"。
4. **兜底与护栏**：模型链选择、首字超时换模型、取消、版本自检全部写成可复现用例（`scripts/e2e-model-chain.cjs`，21 例，用替身 SDK 不消耗额度），并把"不许回退到取第一个未禁用项"写进构建审计。

### 结果

真实页面上端到端实测（`scripts/e2e-real-latency.cjs`，真实接口）：

| 指标 | 改动前 | 改动后 |
| --- | --- | --- |
| 首个候选可见 | 120s 量级 | **1.6s** |
| 3 条全部完成 | 120s 量级 | **1.9s** |
| 截图识别 | 同量级（原本共用同一个模型） | **2.6s** |

### 遗留与下次要看的

- 这次是**纯性能取舍**，没有重跑质量评测。flash 档在"领导 + 接住话头"这类简单意图上表现正常，但**委婉拒绝 / 砍价这类需要绕的表达还没对照过**。等 50 条测试集的"像人评分"做完，再用数据决定是否把更贵的模型放回链上（或按意图分流：简单意图走快模型，难的走大模型）。
- 平台侧的配额是按"积分倍率"计量的（`auto` 实测被分派给 x0.29 的模型，而 flash 档在 x0.06~x0.11）。这次改动顺带把每次生成的积分消耗降了下来，但"配额是否按积分折算"还没有直接证据，暂不作为结论。

## 快照 003 · 2026-10-16（50 条盲评 —— 第一轮回答"回得好不好"）

触发：前面所有评测都在回答「用了没有 / 等了多久 / 有没有崩」，**没有一个数字回答「回得好不好」**。埋点能记下"生成了 3 条"，记不下"这 3 条能不能直接发出去"。这是整条证据链上最大的缺口。

### 方法（为什么绕这么大一圈）

- **测试集**：50 条真实场景，10 个意图各 5 条，覆盖 12 种身份，其中 15 条带风格样本（考"像不像用户自己说话的口气"）。
- **真实生成**：驱动真实页面、走真实云端接口，每条出 3 条候选，共 150 条（不是替身 SDK —— 替身只能验流程，验不了文风）。
- **评测期间把埋点写库拦截成假的 201**：50 次生成会往 `events` 表写 150 行，会污染真实使用统计。实测评测前后 `events` 表行数不变。
- **两半证据，分开取**：
  - **机器半（可复现）**：对照系统提示词里写死的硬规则逐条查 —— 长度、禁用词、破折号/分号/emoji、三条是否为三种不同策略、**有没有编造上下文里没给过的时间或价格**。判不了的它不判。
  - **人半（盲评）**：150 条候选**洗牌**（确定性种子）、**剥掉意图与身份**，两位独立评分者只看"编号 + 正文"，按 1–5 打分，并标出"会不会直接这样发出去"。
  - 盲评的关键是**评分者不知道这条是什么意图、对谁说的** —— 否则会顺着"这题本来就难"放宽标准。
  - 两位评分者风格有意不同（一位宽松、一位挑剔），只看两人独立结论是否收敛。

### 结果

- 合并均分 **4.6 / 5**（评分者 A 4.81，评分者 B 4.39）
- 分数段：5 分 203 条 / 4 分 76 条 / 3 分 18 条 / 2 分 3 条 / 1 分 0 条
- **需要改（任一位标了"不会直接发"）：15 / 150，即 10%**
- 两位评分者一致性：完全相同 59%｜相差 ≤1 分 99%｜相关系数 0.673 —— 大方向一致，分歧集中在边界个案

**按意图（越靠前越弱）**：

| 意图 | 均分 | 需改 |
|---|---|---|
| 拖延一下 | 4.07 | 4 |
| 道歉认错 | 4.20 | 6 |
| 答应但争取条件 | 4.57 | 1 |
| 催促提醒 | 4.63 | 0 |
| 委婉拒绝 | 4.63 | 1 |
| 砍价谈判 | 4.67 | 0 |
| 答应并推进 | 4.67 | 1 |
| 接住话头 | 4.77 | 0 |
| 表达关心 | 4.77 | 2 |
| 幽默化解 | **5.00** | 0 |

**按身份（越靠前越弱）**：老师 3.25（12 条）｜长辈 4.17｜客户或合作方 4.21｜领导 4.31｜初次认识 4.50｜同事 4.72｜网友 4.75｜同学 4.90｜朋友 4.98｜家人 / 暗恋对象 / 对象 5.00

结论很直白：**对"自己人"（朋友、同学、家人）回得几乎满分，一旦面对"有分寸要求的对象"（老师、长辈、客户、领导）就掉下来。** 越是要端着说话的场合，越容易露怯。

### 关键发现（两位评分者互不知情，却指向同一批东西）

不是"谁觉得不好"的模糊印象 —— 两位评分者在完全隔离的情况下，把最差的几条指向了同一批词：

反复出现的职场书面语：`同步 ×4`、`第一时间 ×2`、`过目 ×2`、`当前节点 ×1`、`按点交 ×1`、`不再找借口 ×1`、`核对到位 ×1`

最差 12 条里的三类问题：

1. **给老师/长辈写"检讨书"**：`抱歉老师，拖了两次是我的责任。这次给我个期限，我按点交，不再找借口。` —— 道歉 + 解释 + 承诺 + 自我保证四段齐全，像工作总结不像人话。
2. **流程黑话**：`我查下当前节点，一会儿同步给你`、`老师，还在收尾，有几个地方想再改改，稍后跟您同步`。
3. **对老师/领导过度工整**：`确实是我的问题……您看我今天补上，明天一早交给您，可以吗？`

意图维度也印证：**"道歉认错"那一档的 13 处违规里，12 处是"替用户编造了上下文没给过的具体时间"**（"今天一早给你"、"明天上午发你"）—— 道歉本身没写好，还顺手许了没影的承诺。

### 对应改动（V0.18，纯提示词，不动视觉层）

只改三处**有证据**的，并**主动排除一处没证据的**：

1. **规则 2 禁用表补入职场书面语**：`同步 / 过目 / 第一时间 / 当前节点 / 核对到位 / 按点交 / 不再找借口`。
2. **规则 6 强化不编造**：新增「更不要替用户编造没给过的具体动作（比如「我请半天假」「蛋糕我已经买好了」）。拿不准就用模糊说法」。
3. **意图指南补两条**：拖延一下 ——「不要报流程黑话，也不要写成分点汇报」；道歉认错 ——「别写成检讨书：一两句话就够，不要凑齐道歉 + 解释 + 承诺 + 自我保证四段；不要加「我按点交」「不再找借口」」。
4. **没有动**「您 / 你」的语气规则。盲评里对长辈/老师用"您"是中文里该有的分寸，不是缺陷。中途试过放宽（结果"您"从 6 处漂到 40 处），已回退原样 —— **没有证据的"改进"就是凭空引入风险**。

### 前后同口径对比（V0.17 vs V0.18，各 50 条，用同一套规则核查）

两份原始结果都拿**当前这版核查脚本**重跑，保证是同一把尺子（V0.17 的旧核查口径会把"对长辈用您"也记成违规，已统一收窄）：

| 指标 | V0.17 | V0.18 |
| --- | --- | --- |
| 平均回复长度 | 18.8 字 | 18.7 字 |
| 0 违规的用例 | 40/50（80.0%） | **44/50（88.0%）** |
| 违规总计 | 22 处 | **9 处** |
| 职场书面语 | 3 | 1 |
| 疑似编造 | 14 | 2 |
| 误用「您」 | 4 | 4 |
| 道歉认错（违规数 / 平均长度） | 13 处 / 30.3 字 | **1 处 / 26.3 字** |

怎么读这张表：

- **"职场书面语"这一行要当回归护栏看，不是独立证据。** 禁用词表就是盲评点出来之后写进提示词的，两边是同一份名单 —— 所以 V0.18 掉下来只说明"改动生效了、没有回退"，**不能**拿来宣称"质量变好了"。真正的证据在盲评那一节：**先由两位独立评分者说出这批词，才有的改动**。机器核查在这里的角色是防回退，不是当裁判。
- **"道歉认错"从 13 处违规 / 30.3 字掉到 1 处 / 26.3 字**，是这次改动最直接的效果 —— 那 12 处正是"替用户许了没影的时间承诺"，来自规则 6 的加强，与禁用词表无关，算相对独立的改善。
- **"疑似编造"14→2 要打折看**：那 14 处里夹着核查脚本的误报（例如某条上下文已给了"周一"，脚本仍标了）。真实改善是"道歉里凭空许诺时间"这一类没了，但不要把它当成"编造问题解决了 86%"。
- **"误用您" 4→4 一字未变**，恰好反证语气规则确实没被改动过 —— 有意的对照。
- 平均长度几乎不动，说明改动**没有把回复写长或写短**，只换了用词。

### 遗留

- 50 条只够**定位**，不够下结论。下一步应扩到 100+ 条、**换一批评分者**（避免同一批人形成评分习惯）、并考虑让评分者看一眼"意图"再评 —— 现在连意图都藏了，可能低估了"该端着的场合确实该端着"的那部分。
- **全自动评分仍不可信**：这一轮机器只做硬规则核查，主观好坏还是靠人。要把"像人评分"变成能每天跑的指标，还需要一批人工标注样本做校准。
- 这一轮评的是 **V0.17 的产出**；V0.18 的改动只是按它的发现去改，**盲评本身没有在 V0.18 上重跑**。下一轮盲评要同时覆盖新版，并用同一批评分者做前后对照。
